# fedproc-ledger — project rules

## What this is
Research + open model + dataset: extract the *incorporation status* of every FAR/DFARS clause
mention in US federal solicitations, and build a verified "clause ledger" per solicitation.
Full plan: docs/PLAN.md. Decisions log: docs/decisions.md. Pre-registration: docs/preregistration.md.

## Non-negotiables
- No invented numbers. Every reported number comes from results/*.json written by code here.
  Tables in README/paper/model card are generated by `fl report`.
- No invented citations or regulation facts. Fetch, record URL + date, then use.
- The model never generates clause numbers. Numbers come from regex candidates over the
  document text and are validated against the eCFR registry. The model only classifies.
- Test sets are frozen once created (hash in docs/decisions.md). Never tune on test.
- Secrets only in .env. Never commit data/. Never log API keys.
- Ask Raihan before: spending >$5 in one run, deleting data/raw, new dependencies,
  pushing to GitHub/HF, changing the label schema after annotation starts.

## Stack
Python 3.11, uv, Typer CLI (`fl`), PyMuPDF, python-docx, pandas/pyarrow, httpx, tenacity,
transformers, datasets, accelerate, torch, scikit-learn, scipy, optimum + onnxruntime,
streamlit (annotation), pytest, ruff, mypy (src only).
Optional: vllm (Linux/WSL2) for local LLM baselines; anthropic SDK for API baselines;
pytesseract or doctr for OCR.

## Layout
src/fedproc_ledger/{acquire,registry,extract,candidates,rules,label,annotate,data,model,baselines,eval,serve}
configs/  docs/  scripts/  tests/  results/ (small JSON, committed)  data/ (gitignored)  paper/

## Commands
uv sync · uv run pytest -q · uv run ruff check . · uv run fl --help
Each pipeline step is an `fl` subcommand that reads/writes files under data/ and results/
and writes a manifest (inputs, outputs, git SHA, config hash, timestamp).

## Style
Small pure functions, typed. Every rule/heuristic has a pytest case taken from a real
document snippet (store snippets in tests/fixtures/, never whole documents).
Log decisions (what, why, alternatives) in docs/decisions.md as you go.

## Session protocol (added by the agent; not part of the original spec)
- Resume from `docs/STATE.md` (current phase, last finished step, open questions). Update it after every step, before stopping.
- Long jobs run detached (nohup) with a log under data/logs/; after any interruption (power loss, crash) check the log and the manifest before trusting a result, and never count an infrastructure failure as a result.
- Commit locally after each finished step. No push, no GitHub repo, no Hugging Face upload without Raihan's OK.
- The full phase-by-phase procedure is `docs/EXECUTION_PLAN.md`; the spec it implements is `docs/PLAN.md` (the original `fedproc-v1.md`).
